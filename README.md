## 메모는 서버 함수를 거쳐 읽습니다

화면은 더 이상 `data.json`을 직접 읽지 않습니다. 대신 Vercel의 서버 함수 `api/memos.mjs`(주소: `/api/memos`)를 부르고, 함수가 Supabase의 `memos` 테이블에서 가상 메모 네 건을 읽어 돌려줍니다.

```
화면(브라우저) → /api/memos (Vercel 서버 함수) → Supabase memos 테이블
```

### 환경변수 (Vercel 프로젝트 설정에 등록)

| 이름 | 용도 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 주소 |
| `SUPABASE_SECRET_KEY` | 서버 전용 비밀 키 |

- 두 값은 서버 함수만 읽습니다. 브라우저 파일, 응답, 로그에 넣지 않습니다.
- 실제 값은 저장소에 올리지 않습니다. 로컬 시험용 `.env` 파일을 쓴다면 `.gitignore`에 넣습니다.
- 테이블은 RLS를 켜 두었고 anon·authenticated 권한을 모두 회수했습니다(`memos.sql`). 그래서 브라우저가 Supabase를 직접 읽을 방법은 없고, 서버 함수만 비밀 키로 읽습니다.

### 알려진 약점: 함수는 아직 공개 주소입니다

- `/api/memos`는 로그인 확인이 없어서, 주소를 아는 사람은 누구나 불러 네 건의 메모를 읽을 수 있습니다.
- 비밀 키는 숨겨지지만 **메모 내용은 보호되지 않습니다.** 지금은 가상 메모뿐이라서 감수하는 상태입니다.
- 요청 횟수 제한도 없어서 반복 호출을 막지 못합니다.
- `owner_id` 칸은 비어 있고 아직 쓰지 않습니다.
- 실제 개인 자료를 넣기 전에 로그인 확인과 `owner_id` 기준 조회를 먼저 붙여야 합니다.

## 가상 메모 문장 확인 절차

가상 메모 문장이 공개 파일에 남아 있는지 직접 검색해서 확인합니다. 아래는 확인할 때마다 같은 순서로 따라 합니다.

### 1. 검색어

네 문장에 공통으로 들어 있는 `실습용 가상`을 씁니다. 개별 문장은 아래와 같습니다.

- `실습용 가상 과제 기록`
- `실습용 가상 포트폴리오 기록`
- `실습용 가상 리추얼 기록`
- `실습용 가상 행정 기록`

명령에서는 `grep -F`, `git grep -F`처럼 `-F`(글자 그대로 찾기)를 붙입니다. `data.json`의 `sampleMarker` 값은 메모 문장이 아니므로 검색 대상이 아닙니다.

### 2. GitHub 최신 파일

저장소를 새로 내려받아 기본 브랜치의 최신 파일을 검색합니다. 웹의 코드 검색은 반영이 늦을 수 있어서 내려받은 파일로 확인합니다.

```bash
git clone <저장소 주소> check-latest
cd check-latest
git grep -nF "실습용 가상" || echo "(검색 결과 없음)"
```

브랜치가 여럿이면 `git branch -r`로 목록을 보고, 배포에 쓰는 브랜치마다 `git grep -nF "실습용 가상" origin/<브랜치 이름>`을 실행합니다.

### 3. 옛 공개 커밋

최신 파일에서 사라져도 과거 커밋에는 남을 수 있습니다. 어느 커밋에 있었는지 찾아 기록합니다.

```bash
for c in $(git rev-list --all); do
  git grep -qF "실습용 가상" "$c" && git log -1 --format="%h %ad %s" --date=short "$c"
done
```

여기에 나온 커밋은 파일 안에 문장이 실제로 들어 있는 커밋이고, 공개 저장소에 남아 있는 옛 노출로 기록합니다. 문장을 지운 커밋은 목록에 나오지 않는 것이 정상입니다. (`git log -S "실습용 가상"`은 문장을 지운 커밋까지 보여 주므로 개수를 세는 데 쓰지 않습니다.)

### 4. 현재 배포 파일

배포 주소에서 화면이 불러오는 파일을 하나씩 받아 검색합니다. 파일 목록은 저장소의 파일과, 브라우저 개발자 도구 Network 탭에서 보이는 요청을 보고 정합니다.

```bash
SITE=https://<배포 주소>
for p in / /data.json /index.html; do   # 화면이 불러오는 파일 경로를 더해 적습니다
  echo "== $p"
  curl -s -o body.tmp -w "상태 %{http_code}\n" "$SITE$p"
  grep -nF "실습용 가상" body.tmp || echo "(검색 결과 없음)"
done
rm -f body.tmp
```

`/data.json`이 404면 그대로 기록하고, 200인데 `notes`에 문장이 있으면 노출로 기록합니다.

### 5. 옛 배포

Vercel은 새로 배포한 뒤에도 이전 배포를 각자의 고유 주소로 남겨 둡니다. Vercel 대시보드의 Deployments 목록에서 이전 배포 주소를 모두 모아 같은 방법으로 검색합니다.

```bash
curl -s "https://<옛 배포 주소>/data.json" | grep -nF "실습용 가상" || echo "(검색 결과 없음)"
```

문장이 나오는 옛 배포는 삭제하기 전까지 남아 있는 노출로 기록합니다. 배포 보호 설정 때문에 접근이 막혀 있어도, 삭제한 것이 아니라면 남아 있는 배포로 기록합니다.

### 6. 공개 API

```bash
curl -s "https://<배포 주소>/api/memos"
```

이 주소는 의도적으로 메모 네 건을 돌려줍니다. 검색 결과 "없음"으로 셀 수 없고, 아래 7번에서 공개 API의 약점으로 따로 기록합니다.

### 7. 기록

확인: 검색 결과와 공개 API의 남은 약점을 각각 기록합니다.

| 날짜 | 확인한 곳 | 검색 결과 |
| --- | --- | --- |
| | GitHub 최신 파일(기본 브랜치) | |
| | GitHub 다른 브랜치 | |
| | 옛 공개 커밋 | |
| | 현재 배포 파일 | |
| | 옛 배포 | |

공개 API의 남은 약점은 검색 결과 표와 따로 적습니다. 「알려진 약점: 함수는 아직 공개 주소입니다」의 항목 중 아직 남은 것을 날짜와 함께 옮겨 적습니다.

### 기록에 쓰는 말

- 최신 파일과 현재 배포에서 검색 결과가 없으면 "현재 최신 파일과 현재 배포에서는 검색되지 않음"까지만 씁니다.
- 옛 공개 커밋이나 옛 배포에서 문장이 나오면 그 개수와 주소를 적고, 정리하기 전까지 **"과거 노출은 해소되지 않음"**으로 씁니다.
- 옛 커밋과 옛 배포가 하나라도 남아 있는 동안은 "과거 노출이 해소됐다", "안전하다"고 쓰지 않습니다.
- 커밋 기록을 고쳐 쓰거나 옛 배포를 지워도, 이미 복제되었거나 캐시된 사본까지 없어졌다고 단정하지 않습니다.
- 공개 API가 메모를 돌려주는 것은 검색 결과가 아니라 약점으로 기록합니다.
